4. Caminho critico · 10 tarefas

Da pra terminar em 2 semanas com 5 pessoas no pool aberto.

T15 contas Kaggle phone-verified + GPU ativadaCRITICA
Cada fundador 1 conta Kaggle, phone verify, ativar T4. Dia 1.
T2Conta org HuggingFace + W&B + secretsCRITICA
Aceitar convite org iterate-labs no HF e W&B. Gerar HF token write. Configurar como Kaggle Secrets (HF_TOKEN, WANDB_API_KEY).
T3Baixar e olhar os 3 datasets HFMUST
Rodar load_dataset nos 3, ver schema, contar tokens reais, escolher campo de texto. ~2h dev.
T4Script unico de continued pretrain Unsloth + TRLMUST
Implementacao funcional em train/continued_pretrain.py. Carrega Qwen-Coder-3B, mistura 3 datasets, treina SFT com LoRA r=32, push HF Hub a cada 200 passos. Ja existe stub no repo, precisa testar smoke run de 100 passos.
T5Decontamination CVE-ID dedup vs CyberGymMUST
So a camada de CVE-ID (rapido). Tira de PrimeVul/BigVul/DiverseVul qualquer CVE que aparece em CyberGym 1507. Ja existe stub funcional em eval/check_decontamination.py, precisa rodar e ver resultado.
T6Schedule de revezamento 3 sessoes KaggleMUST
Atualizar SCHEDULE.md com 3 slots de 9h cobrindo 25h total. 3 fundadores tomam 1 cada. Resto do time observa.
T7Sessao 1 · primeiros 9h treino (smoke)CRITICA
Primeiro fundador roda notebook Kaggle. Confirma que treino comeca, loss desce, push HF Hub funciona. Salvar revision step-1.
T8Sessao 2 · continua 9hMUST
Segundo fundador resume from step-1. Push step-2.
T9Sessao 3 · finalizar Caracal Base 3B v0MUST
Terceiro fundador. Push final caracal-base-3b-v0 como repository tag estavel.
T10Avaliacao basica · 50 vulns CyberGymMUST
Carregar Caracal Base 3B v0 + Qwen Coder 3B base zero-shot. Comparar pass@1 em 50 vulneraveis CyberGym subset. Pareto: ganho ou perda?

7. Como treinar (concreto)

7.1 No Kaggle, criar notebook novo, copiar codigo abaixo

!git clone https://github.com/iterate-labs-ai/caracal-1.git
%cd caracal-1
!git checkout dev
!pip install --quiet 'unsloth[kaggle-new] @ git+https://github.com/unslothai/unsloth.git'
!pip install --quiet trl peft datasets huggingface_hub wandb pyyaml

from kaggle_secrets import UserSecretsClient
import os
secrets = UserSecretsClient()
os.environ['HF_TOKEN'] = secrets.get_secret('HF_TOKEN')
os.environ['WANDB_API_KEY'] = secrets.get_secret('WANDB_API_KEY')
!huggingface-cli login --token $HF_TOKEN --add-to-git-credential
!wandb login $WANDB_API_KEY

# Variaveis do seu slot:
SESSION = 1
RESUME = None   # None se for sessao 1; senao 'step-7000' etc
OUTPUT = 'step-7000'
STEPS = 7000

import subprocess, sys
resume_arg = ['--resume-from', f'huggingface://iterate-labs/caracal-base-3b-v0@{RESUME}'] if RESUME else []
subprocess.run([sys.executable, 'train/continued_pretrain.py',
                '--config', 'train/configs/caracal_base_3b.yaml',
                *resume_arg,
                '--steps-to-run', str(STEPS),
                '--output', './ckpt-out',
                '--hf-revision-out', OUTPUT], check=True)

7.2 Apos sessao terminar (manualmente)

  1. Verificar revision pushed em huggingface.co/iterate-labs/caracal-base-3b-v0
  2. PR pequena editando SCHEDULE.md: trocar slot N de pending para done · revision step-XXXX
  3. Sinalizar Discord/grupo: "sessao N completa, revision XXXX disponivel"
  4. Proximo do relay configura RESUME = ultima revision e roda

8. Apos v0 · decidir baseado em medicao

Quando Caracal Base 3B v0 estiver no HF Hub e avaliacao basica em 50 vulns rodada, time se reune e decide:

Resultado v0Proximo passo
Score sobe vs Qwen base (mesmo <5 pontos)Continuar caminho · adicionar mais datasets (v1 com Project Zero + scraping NVD)
Score nao moveRepensar: talvez precisa mais tokens, ou mais epocas, ou dataset com PoCs estruturados
Score caiHyperparam errado ou contaminacao mascarando avaliacao · debug
Treino quebra antes de v0 ficar prontoBug no script · debug + retry

So apos v0 funcionar e a gente decide se adiciona:

  • Mais datasets (scraping NVD, Project Zero, etc)
  • 5 modulos LoRA especialistas
  • Modal sandbox para RL com PoC executando
  • Colab Pro+ para acelerar (se Kaggle T4 demorando demais)
  • Avaliacao completa CyberGym 1507
  • Caça zero-day em held-out 30 CVE 2026
  • Paper preprint arXiv

10. Glossario rapido

TermoSignificado
LoRA r=32Adapter de baixo posto. Treina ~1% dos parametros. Salva 130MB em vez de 6GB.
SFTSupervised Fine-Tuning. Treino com pares (input, output esperado).
Continued pretrainContinua o treino com corpus novo antes do SFT.
HF HubHuggingFace Hub. Onde a gente publica modelos.
RevisionSnapshot imutavel de um modelo no HF Hub (tipo commit no git).
Kaggle T4Placa de video gratis no Kaggle (16GB). Aguenta modelo 3B sem quantizar.
UnslothFramework de treino otimizado. 2-5x mais rapido que TRL puro. 80% menos memoria.
CyberGymBenchmark Berkeley com 1507 vulnerabilidades reais. Avaliacao.
