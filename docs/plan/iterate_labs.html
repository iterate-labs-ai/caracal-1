2. Os 5 modulos de Caracal (sem dono fixo)

Caracal-1 v1 e composto por 5 modulos LoRA especialistas sobre um Caracal Base compartilhado. Cada modulo e LoRA r=32 de 130MB. Conversam via protocolo JSON estruturado. Qualquer fundador treina qualquer modulo conforme tarefa disponivel no pool. Ao longo de 4 sprints todos terao tocado em todos os modulos.

Modulo 1 · Recon

130MB LoRA r=32 · embodied via gdb live · STRETCH inicial, MUST sprint 2

Scout codebase, prioriza alvos. Le call graphs estaticos. Novidade radical: opera tambem via comandos gdb/mi reais em sessao live. Le state runtime, valores de variaveis, backtrace. Aprende debugging como skill core, nao chuteira chain-of-thought.

Modulo 2 · Hypothesizer

130MB LoRA r=32

Enumera 3 hipoteses de bug class por target. Output estruturado: tipo CWE, primitiva de exploit, dificuldade estimada, primitivas necessarias do banco. Treinado em writeups de CTF + Project Zero + Trail of Bits.

Modulo 3 · Crafter

130MB LoRA r=32 · state machine policy

Escreve PoC concreto, segue state machine rigida: ANALYZE → INSTRUMENT → EXECUTE → REFINE. Recompensa parcial por transicoes validas. Counterfactual mutator (gera "mutacao minimal que NAO triggaria") amarra reward causalmente.

Modulo 4 · Validator

130MB LoRA r=32 · SMT bounded Z3

Gera specification formal do bug em Hoare-lite. Invoca Z3 bounded (depth 5) pra verificar match entre spec e PoC. Causal grounding por prova, nao so empirico. Reward por consistencia spec ↔ PoC ↔ execucao.

Modulo 5 · Patcher

130MB LoRA r=32 · anti-supressao check

Gera unified diff. Anti-supressao check (re-roda sanitizer em 10 inputs adjacentes pra pegar catch-and-ignore). Preserva coverage existente. Reward por patch valido + nao quebrar testes + nao suprimir bugs adjacentes.

11. Harness recursivo (6 loops self-improving)

Caracal-Ω-Recursive opera em 6 loops aninhados. Cada loop muta um nivel da pilha. Boundary intocavel: kernel-D (evaluator, sandbox, reward registry, budget enforcer, classes config). So humanos editam kernel-D. Os 5 loops abaixo dele evoluem por si proprios contra o evaluator congelado. Padrao Darwin Godel Machine (Sakana 2025) mais SICA (17→53% SWE Bench Verified) mais salvaguardas STOP-anti-reward-hacking.

11.3 Detector STOP-pattern

Probe automatica roda em cada gate de eval. Detecta tentativas do loop de:

  • Editar arquivos do kernel-D (rejeitado por classes config + Action C4)
  • Aumentar proprio budget (rejeitado por enforcer kernel)
  • Reduzir proprio isolamento (sandbox config nunca acessivel)
  • Suprimir crashes em vez de patchar (anti-supressao check Action C8)
  • Coletar canary strings inseridas em corpus (probe anti-leak)

Trigger = trajetoria descartada + flag em harness/incidents/YYYY-MM-DD.md + review humano.

12. Estrategia Kaggle: 5 contas relay race

Cada conta treina 9h consecutivas, push checkpoint, proxima conta resume. Total 80h Caracal Base = 9 sessoes de ~9h distribuidas em 2-3 dias.
